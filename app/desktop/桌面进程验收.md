# 桌面进程验收清单

本清单验收真实安装版中的桌面壳与本地服务协作，覆盖启动握手、运行中故障、退出处理和任务重启。`npm run test:desktop` 直接启动随包 Node 并显式传入 `LITERATURE_LIBRARY`，只验证安装布局和首次导入，不覆盖这里的行为。

## 前置条件

- 已用 `npm run desktop:build` 生成并安装当前构建；记录版本号、构建时间和安装路径。
- 验收“默认库路径”时使用安装版可执行文件，不要用 `start-desktop.cmd`（它会设置 `LITERATURE_LIBRARY`）。
- 准备本机 Python；执行 `run.py repair` 时优先用项目虚拟环境 `app/downloader/.venv`。
- 每项结束后保存截图或命令输出；结果只按实际观察记录，未执行的项写“跳过”。

在 PowerShell 中可用下面的命令定位当前安装版的服务进程和端口：

```powershell
function Get-ZhiyueServer {
  Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
    Where-Object { $_.CommandLine -like '*server.js*' } |
    Select-Object -First 1
}
$server = Get-ZhiyueServer
$server | Select-Object ProcessId, CommandLine
$port = (Get-NetTCPConnection -OwningProcess $server.ProcessId -State Listen |
  Select-Object -First 1).LocalPort
Invoke-RestMethod "http://127.0.0.1:$port/api/status" | Select-Object root, python
```

## A 默认库路径定位

确认当前终端、用户和系统环境都没有设置 `LITERATURE_LIBRARY`：

```powershell
[Environment]::GetEnvironmentVariable('LITERATURE_LIBRARY', 'User')
[Environment]::GetEnvironmentVariable('LITERATURE_LIBRARY', 'Machine')
```

步骤：

1. 启动安装版，等待文献列表加载完成。
2. 用上面的命令读取 `/api/status` 的 `root`。
3. 对照系统“文档”已知文件夹：`[Environment]::GetFolderPath('MyDocuments')`。预期 `root` 为 `<该目录>\Zhiyue\library`，不要求字面等于 `%USERPROFILE%\Documents`（文档目录可能被 OneDrive 重定向）。
4. 检查库内存在 `papers`、`notes`、`synthesis`、`outputs`、`.zhiyue/catalog/文献索引.json`。
5. 记录 `README.md` 的 SHA-256，托盘退出后重新启动，确认库路径不变且 README 未被改写。

## B 握手后的服务崩溃

步骤：

1. 启动安装版并等界面完全加载。
2. 用 `Get-ZhiyueServer` 取得 Node 的 PID，执行 `taskkill /PID <PID> /F`。
3. 观察窗口：预期约 2 秒内回到启动页，状态文字为“本地服务意外停止（退出码 N）。请从托盘菜单退出 Zhiyue 后重新打开。”，有 stderr 时附“最近输出”。
4. 确认没有自动拉起新服务：`Get-ZhiyueServer` 应为空，窗口不会自行恢复。
5. 从托盘退出后重新启动，确认文献库正常加载、可以继续操作。
6. 重复一次在窗口隐藏到托盘时杀死服务，再显示窗口，确认错误页仍然存在。

记录：从杀死进程到出现错误页的时间、错误文案、是否有“最近输出”、崩溃前是否有正在运行的任务。

## C 归档中退出再重启

步骤：

1. 准备 3–5 个可导入的 PDF（建议用合成 PDF，避免影响真实文献）。在界面批量导入并开始归档；若归档过快，增加文件数量后重试。
2. 在任务中心确认任务为运行中，立即从托盘“退出”。
3. 确认 Node 进程已消失（`Get-ZhiyueServer` 为空）。
4. 重新启动，检查任务中心：原 `running`/`queued` 任务应为失败，错误为“进程重启，任务已中断；请检查批次后手动续跑”。核对 `.zhiyue/data/jobs.json` 中的状态已持久化。
5. 检查文献库：没有重复的 L 编号，没有指向不存在文件的 README 行；如存在 `prepared` 归档事务，先按归档事务规则核对，再在项目根目录执行：

   ```powershell
   app\downloader\.venv\Scripts\python.exe app\downloader\run.py --root "<库路径>" repair
   ```

6. repair 后重新读取 `/api/library`，确认索引重建；续跑或重新提交剩余条目，确认 L 编号继续递增且不覆盖已有文件。

如果任务在退出前已经完成，本次记录为“未覆盖”，换更大的批次重试，不能把完成后的重启当作中断恢复证据。

## D 退出与更新前退出

步骤：

1. 点击窗口关闭按钮，确认窗口隐藏、Node 仍在、正在运行的任务继续；托盘“显示 Zhiyue”能恢复窗口。
2. 在任务运行中从托盘“退出”，确认 Node 进程消失；再次启动后任务按 C 的预期标为中断。
3. 用任务管理器或 `Stop-Process -Name zhiyue-desktop -Force` 强制结束桌面进程，等待 2 秒后检查 `Get-ZhiyueServer`：预期为空（作业对象兜底）。重新启动后确认库可读，运行中任务标为中断。
4. 如具备更新源和已签名安装包：设置 `ZHIYUE_UPDATE_ENDPOINT`，托盘“检查更新”，确认下载安装。安装器运行前 Node 应已结束；安装完成后应用自动重启并加载原文献库。没有更新源时记录“跳过（缺少更新源）”。

## E 安装布局回归

1. 运行 `npm run test:desktop`，记录通过/跳过原因。它覆盖安装布局、空库初始化、离线导入和重启后读取。
2. 在真实 NSIS 安装版上复跑 A、B、D；确认安装目录包含 `resources/runtime/node/node.exe`，卸载后用户文献库不被删除。
3. 明确记录未覆盖项：NSIS 注册表与快捷方式、WebView2 内部行为、更新源签名、真实模型服务。

判定说明：

- B 中“不自动重启”是当前设计，不是失败；失败指没有显示错误页、显示了错误文案但服务仍在运行，或错误页导致应用无法从托盘退出。
