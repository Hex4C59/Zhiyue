# Zhiyue 桌面界面与本地服务

维护日期：2026-11-17。通过图形界面浏览本项目的真实目录，在右侧使用 Pi Agent 阅读、讨论与下载论文。原文沿用现有位置，书目和来源记录仍是资料依据。

界面采用中性黑白灰、紧凑导航与列表排版，减少装饰文案和卡片边框。正文、次要信息与控件保持足够对比度，辅助文字不使用难以辨认的浅灰。宽屏下 PDF 适宽预览最多 880 像素，放大时按比例扩展；原文翻页、笔记、Pi Agent 与下载操作沿用原有入口。

网页字体优先使用本机已安装的 Anthropic 系列：导航、按钮和表单用 Sans Variable Text，助手回答、阅读笔记和阅读标题用 Serif Variable Text，代码、编号和日志用 Mono Web。中文分别搭配 Noto Sans SC / Noto Serif SC。样式只通过 local() 引用已核对的字体完整名称，不复制或分发字体文件；未安装相应字体的设备使用系统回退字体。PDF 页面图片和选择文字层继续采用原文的排版度量。

助手面板采用紧凑页头、论文标签和自适应输入框；连接状态显示为圆点，鼠标停留可查看详情。底部保留附件、模型和发送操作；模型选择支持搜索、方向键选择和 Esc 关闭，生成时发送按钮切换为停止按钮。没有选中论文时隐藏上下文栏，输入框不显示额外说明文字，快捷键与附件操作沿用原有行为。

宽屏下可拖动分类栏、文献列表和助手栏之间的三条竖向分隔线调整宽度，阅读区随之伸缩。双击某条分隔线恢复对应栏的默认宽度；用 Tab 聚焦分隔线后，可按左右键微调（Shift 加速），Home/End 调到最小/最大宽度。拖动时按 Esc 撤销。宽度保存在当前浏览器，刷新后恢复；窗口缩小时自动限制各栏宽度，保留阅读空间。平板和手机继续使用原有的面板切换布局。

连续阅读现支持直接选择 PDF 文字并按 Ctrl+C 复制，也可点击“复制本页文字”。页面图片上叠加从当前页提取的透明文字层，缩放和调整栏宽时同步缩放；选择中的页面不会因滚动而释放。纯扫描页、无文字页会显示“本页无文字层”，本功能不自动 OCR。文字编码缺失或图表、公式等特殊排版可能影响复制结果，可切换“浏览器阅读器”核对原文。文字层由本机 `pdfplumber` 生成，仅保存派生缓存，不更改原始 PDF。Python 依赖见 `app/downloader/requirements.txt`（包含 pdfplumber）；提取失败时图片仍可阅读，并显示原因。

## 启动

安装用户从开始菜单打开 Zhiyue，源码调试使用 `npm run desktop:dev`，本机构建完成后也可运行 `.\start-desktop.cmd`。Tauri 会启动本地服务，再在 WebView2 窗口中加载 Vue 界面。构建和文献库路径见[程序结构与维护](../README.md)。

应用使用项目依赖自带的官方 Pi SDK（`@earendil-works/pi-coding-agent`，当前 1.5.2）；模型与登录配置仍读取本机 `~/.pi/agent`（可用 `PI_CODING_AGENT_DIR` 指定）。可在助手面板的“模型与密钥”中保存或清除 API 密钥、更换默认模型、调整思考强度与上下文压缩阈值，账号登录仍在终端运行 `pi` 完成；未配置时仍可浏览和整理文献。

论文解析和下载复用已有 Python、pypdf、curl、Poppler 与 InstSci。启动前可运行 `.\scripts\download.ps1 doctor` 检查。本地服务优先使用 `LITERATURE_PYTHON` 指定的 Python，其次为 `app/downloader/.venv` 和 PATH。

## 阅读和提问

2026-11-17：右侧只使用 Pi Agent，不再提供助手切换。网站改用项目依赖中的官方 Pi SDK 1.5.2，桌面安装包随包分发运行依赖，不再查找本机 Pi 的托管安装；模型和认证配置仍复用本机 `~/.pi/agent`。首次使用先在终端运行 `pi` 完成登录，或点击助手页头的设置按钮填写 API 密钥。设置面板可更换网站新会话的默认模型（同时写入 Pi 全局设置）、保存和清除 API 密钥；账号登录（OAuth）仍需在终端 Pi 中完成。`PI_CODING_AGENT_DIR` 可指定 Pi 配置目录。

Pi 的网页会话开放六项文献工具与 `read_skill`，支持流式回答、停止、论文上下文、图片与提取后的文件附件。技能从文献库 `.zhiyue/skills/` 扫描：系统提示只放名称、描述与路径，正文由 `read_skill` 按需读取；不加载 Pi 的全局扩展、全局技能或任意 shell/文件写入工具，技能内的 `.md` 以外文件不会被读取。输入框以 `/` 开头时显示斜杠命令菜单（↑↓ 选择、Enter/Tab 插入、Esc 清空），命令由 `/api/commands` 提供、在 `/api/chats/:id/commands` 执行：`/help`、`/skills` 与 `/compact` 由服务端直接生成回执消息，不进入模型上下文；`/skill:<名称>` 把技能说明展开成本轮用户要求发给模型，聊天记录只保留用户输入的单行指令。Pi 没有可用模型时，页面提示配置模型与密钥，并提供设置入口和重新检测；模型不支持图片时会明确报错。模型返回的推理内容单独收在消息上方的“推理过程”折叠块中，默认收起，随回答增量追加。Pi 生成的笔记先作为草稿显示在右侧，用户点击“保存为笔记”后才写入 `library/notes/`，同名文件不会被覆盖，必要时自动添加序号；选择丢弃不会留下文件。Pi 聊天显示记录在 `library/.zhiyue/data/pi/chats.json`，Pi SDK 会话在 `library/.zhiyue/data/pi-sessions/`。旧 Codex 聊天仍保存在 `library/.zhiyue/data/chats.json`，网站不再读取或显示。

- 左侧按主题、年份、阅读进度或收藏筛选，也可以搜索题名、作者和 L 编号。“分类”标题旁的加号新建文件夹，鼠标移到文件夹行或键盘聚焦时显示铅笔按钮重命名；分类对应 `papers/` 下的实际目录，空文件夹也会列出，新建时自动接续两位编号前缀。重命名保留编号，并同步改写 README、笔记、成果、来源记录、批次台账和索引中的路径；改名与后台归档通过库写锁串行，归档进行中会提示稍后重试。中间默认使用“连续阅读”：PDF 页面纵向排列，滚轮可跨页阅读，工具栏自动显示当前物理页序；仍可用前后页按钮或页码跳转，并保持当前位置缩放。在阅读区按住 Ctrl 滚动鼠标滚轮（触控板捏合同样上报为 Ctrl+滚轮）可按 10% 步进缩放页面，范围 100%–200%，缩放时保持当前页内阅读位置；普通滚轮不受影响，工具栏的缩小、适宽和放大按钮与缩放比例保持同步。页面图像按需加载附近页，离得较远的图像会释放，再滚回时重新加载。也可切换已有 Markdown 笔记；笔记模式下工具栏提供删除按钮，确认后把文件移到 `library/.zhiyue/trash/notes/`（带时间戳前缀，可手动找回），笔记计数与索引同步刷新。原文可单独打开并使用浏览器 PDF 阅读器选择文字、搜索。
- 文献列表上方的“导入 PDF”打开导入对话框：可多选 PDF、选择整个文件夹或把文件与文件夹拖入，一次最多 100 个、单个最大 25 MB；文件夹中的来源记录等非 PDF 文件会被忽略。首次加入单个文件夹时，归档分类按文件夹名自动预选同名分类（忽略开头的编号），没有同名分类时预选以该文件夹名新建的“网站导入（新建）”分类，提交前按编号规则创建目录，归档只使用批次台账中已存在的分类；手动改过分类后不再覆盖，文件夹名不能用作 Windows 目录名时保持原分类。每个文件按文件名预填题名，可逐条修改并展开填写作者、年份和 DOI，统一选择归档分类；勾选已核对题名与作者后提交。文件先上传到网站数据目录，再由统一下载工具依次执行导入、逐条附加、按用户确认记录身份和整批归档；批次、来源记录、README 索引和编号照常生成。SHA-256 相同或库内已归档的 PDF 会跳过并列出原有 L 编号，不重复归档。
- 选择论文会把编号和归档路径加入右侧上下文，最多 6 篇；上下文标签可移除。提供索引不等于已阅读全文，Pi Agent 可以继续调用原文页读取工具。
- 右侧支持流式文字问答、模型选择、新会话、历史会话、停止生成、审批请求处理、笔记草稿预览和补充问题。会话保存在当前文献库中。
- 点击附件按钮、拖入文件或粘贴图片。每次最多 8 个文件，每个最多 25 MB。支持 PNG/JPEG/WebP/GIF、PDF、TXT/MD/CSV/TSV/JSON、DOCX/XLSX/PPTX。
- 图片作为图像交给 Pi Agent；PDF 初始提取前 8 个物理页，原文工具每次最多 12 页。扫描 PDF 不自动 OCR，空文字层会明确标出；需要时可继续读取或渲染所选原文。Office 附件提取有限的正文 XML 文字，不保证图表、公式、工作表结构和版式。
- 收藏和阅读进度仅在用户操作时写入，生成笔记、打开原文或提问不会自动标记已读。网站标记独立存于 `library/.zhiyue/data/reading.json`，不推断或覆盖旧笔记里的阅读状态。

聊天与附件存放在本机；发送问题时，所选论文索引、实际读取的原文内容、图片和附件提取文字会交给当前助手已配置的模型服务。提示中还包含文献库根目录、选中文献与附件的本机绝对路径；选中只决定初始提示，页读取工具可访问任何已索引的 L 编号。Pi 使用其配置的模型服务、网络、计费及数据处理设置，并非默认离线运行。具体范围见[架构说明](../../ARCHITECTURE.md#模型上下文与数据外发)。

## 下载任务中心

可以在任务中心按行输入 DOI 或题名，也可粘贴 JSON 条目数组。选择归档分类与下载渠道后提交。优先提供 DOI，题名有歧义时需要补充核对。

一次新任务复用同一套流程：

```text
导入批次 → 本地查重 → 下载或复用 → PDF身份、解析与渲染核验
                                    ↓
                     已核验项归档 → 编号、来源、README和目录更新
                     未通过项保留待办 → 修正信息或人工核对后续跑
```

网页与 Pi Agent 均调用 [统一文献工具](../downloader/README.md)，没有另一套下载器或书目数据库。新任务默认归入 `papers/09_情感综述调研/网站导入/`，可选择其他已有主题；旧批次继续使用原目录。

| 渠道或按钮 | 实际作用 |
| --- | --- |
| 公开来源 | 先查本地，再尝试公开来源；无法获取的记录保留待办 |
| 自动渠道 | 按现有配置尝试渠道，Elsevier 凭据须在启动桌面应用的进程环境中配置 |
| IEEE/机构渠道 | 准备并提交现有 InstSci；需要时在机构工具可见窗口登录 |
| 继续下载 | 对该批次明确重试公开渠道 |
| 提交 IEEE 获取 | 将现有批次提交到机构下载器，不代表 PDF 已取得 |
| 收集机构下载 | 从本批次的固定 InstSci 输出目录匹配并核验 PDF |
| 核验文件 | 复查已记录的文件及身份、解析与渲染结果 |
| 归档入库 | 只归档通过核验的条目，复用已有编号或分配下一编号 |

任务显示“流程结束”表示命令流程结束；是否取得论文应查看“已归档 / 待人工核对 / 待获取权限”等统计与日志。机构浏览器任务异步运行，下载结束后点击“收集机构下载”，再核验和归档。

题名修正、补充候选链接、记录人工目视核对以及分享打包继续使用 [命令行文献工具](../downloader/README.md) 中的命令。网页“导入 PDF”的身份确认以用户勾选“已核对题名与作者”为依据，不代替逐页目视核对。

右侧可以直接提出：

> 搜索本地是否已有 Scherer 2005 的《What are emotions? And how can they be measured?》。没有就下载，核对后归档，告诉我实际任务状态。

> 把下面这些 DOI 下载到语音与会话情感识别分类，保留原版本，未核实的不要归档：……

斜杠命令与技能的关系：不带斜杠时模型按技能描述自行决定是否调用 `read_skill`；`/skill:<名称>` 是显式入口，直接把技能正文放进本轮提示，适合需要强制套用某个流程的场合。技能可写 `disable-model-invocation: true` 只保留命令入口，此时系统提示的能力清单不再列出该技能。想查看当前加载情况可发送 `/skills`，它会列出技能与扫描诊断；`/compact [说明]` 调用 Pi 的会话压缩，把摘要写回同一会话文件，被中断的回答不会重试。

Pi Agent 可用的具名工具：`library_search`、`read_paper_pages`、`download_papers`、`continue_download_batch`、`get_download_status`、`read_skill`、`draft_note`。工具结果提供真实任务 ID 与状态；聊天中创建的任务也会进入任务中心。`download_papers` 与 `continue_download_batch` 直接入队，归档前只做自动身份核验，没有逐篇确认；`draft_note` 只把笔记草稿交给网页预览，用户确认后才写入 `notes/`，不能由模型直接覆盖已有笔记。无需为每个下载需求再写脚本。

## 文件职责与保存

| 位置 | 内容 |
| --- | --- |
| `frontend/` | Vue 3 组件、响应式状态、Markdown 与阅读控制器 |
| `dist/app.js`、`dist/LICENSE.vue.txt` | Vite 构建的浏览器入口及 Vue MIT 许可证 |
| `public/index.html`、`public/css/` | 挂载入口与现有样式，无 CDN 依赖 |
| `src/server.ts` | 本机 HTTP、PDF 范围读取、上传和事件流 |
| `src/lib/paths.ts` | 解析文献库根目录及各内容、程序状态、缓存路径 |
| `src/lib/library.ts` | 读取 `.zhiyue/catalog`、关联笔记、保存用户阅读标记、删除笔记到回收站 |
| `src/lib/chat.ts` | 聊天记录、助手协议、具名工具与审批 |
| `src/lib/assistants.ts`、`src/lib/pi.ts` | Pi Agent 的接入、模型与连接状态 |
| `src/lib/jobs.ts` | 串行调用下载工具，保存断点与任务日志 |
| `src/lib/extract.py` | 只读附件提取，保留读取范围与截断提示 |
| `src/lib/skills.ts` | 扫描 `.zhiyue/skills`，校验 frontmatter 并限制 `read_skill` 的读取范围；`SkillRegistry` 供系统提示、`read_skill` 与斜杠命令共用 |
| `src/lib/commands.ts` | 斜杠命令目录、解析与本地命令回执，技能命令只做校验与展开 |
| `frontend/components/CommandMenu.vue` | 输入框的斜杠命令菜单、键盘导航与插入 |
| `src/lib/preview.ts`、`src/lib/render.py` | 用现有 Poppler 按需渲染单页；源 PDF 保持原样 |
| `test/` | TypeScript 测试源码：HTTP/SSE、任务、PDF 边界与 jsdom 交互（编译后运行） |
| 仓库根 `build/` | `tsc` 输出的服务端、测试与脚本；被 Git 忽略，桌面资源与测试从这里取 |
| `../../library/.zhiyue/data/` | 网站聊天、上传原文件、任务输入和阅读标记；全部被 Git 忽略 |
| `../../library/.zhiyue/skills/` | 指令型技能（每个目录一个 `SKILL.md`）；系统提示只列清单，正文由 `read_skill` 读取 |
| `../../library/.zhiyue/batches/` | 长期下载批次、来源与状态记录 |
| `../../library/.zhiyue/tmp/<批次>/` | 下载候选、接口响应和核验预览 |
| `../../library/.zhiyue/cache/pdf-preview/` | 浏览时生成的单页图像缓存，可从原文重新生成 |

需要迁移时，另行备份论文原文及 `library/.zhiyue/data/`；Git 不包含 PDF、上传文件或聊天。本服务只监听 `127.0.0.1`，并校验 Host、Origin、跨站标记、请求类型与可访问资料路径；这些校验只排除浏览器跨源请求和资料越界，不构成登录鉴权，同机其他程序可以直接调用接口，详见[架构说明](../../ARCHITECTURE.md#本机接口的信任边界)。若 Pi 发起审批请求，请求会显示在右侧，由用户选择允许或拒绝；当前文献工具与 read_skill 不发起这类审批，只有笔记草稿需要用户确认后才写入 `notes/`。

从托盘退出应用会停止本地服务及其子进程。未完成的任务会在下次启动时恢复中断标记，检查对应批次后再续跑。部分归档后遇到错误时，先检查批次与来源记录，必要时用“刷新索引”重建目录。

## 验证与维护

Pi 接入有自动测试，覆盖会话恢复、流式输出、停止后重发、工具调用、模型与路径校验。`npm run check:pi` 可从项目根目录执行可选的真实模型验收：仅发送临时生成的虚构目录、单页 PDF、红色图片与普通文本，不读取真实文献或正式聊天；会使用本机 Pi 配置并产生模型调用，结束后清理临时会话。已在 2026-11-16 验证真实问答、文献工具桥接、PDF 页读取、文本附件及图片识别。

```powershell
npm ci
npm run typecheck
```
