# Zhiyue 桌面界面与本地服务

维护日期：2026-11-17。通过图形界面浏览本项目的真实目录，在右侧使用 Pi Agent 阅读、讨论与下载论文。原文沿用现有位置，书目和来源记录仍是资料依据。

界面采用中性黑白灰、紧凑导航与列表排版，减少装饰文案和卡片边框。正文、次要信息与控件保持足够对比度，辅助文字不使用难以辨认的浅灰。宽屏下 PDF 适宽预览最多 880 CSS 像素，放大时按比例扩展。阅读器根据实际显示尺寸和屏幕像素密度升级可见页的图像，长边最高 4800 像素。高清图就绪后直接替换页图，保留滚动位置与文字选区。

网页字体优先使用本机已安装的 Anthropic 系列：导航、按钮和表单用 Sans Variable Text，助手回答、阅读笔记和阅读标题用 Serif Variable Text，代码、编号和日志用 Mono Web。中文分别搭配 Noto Sans SC / Noto Serif SC。样式只通过 local() 引用已核对的字体完整名称，不复制或分发字体文件；未安装相应字体的设备使用系统回退字体。PDF 页面图片和选择文字层继续采用原文的排版度量。

助手面板采用紧凑页头、论文标签和自适应输入框；连接状态显示为圆点，鼠标停留可查看详情。底部保留附件、模型和发送操作。打开模型选择后先选服务商，再选该服务商的模型。两级都可搜索和使用方向键，Esc 返回上一级或关闭菜单。生成时发送按钮切换为停止按钮，模型选择器仍可用：切换只影响下一条消息，当前回答继续用发出时的模型。没有选中论文时隐藏上下文栏，输入框不显示额外说明文字，快捷键与附件操作沿用原有行为。

宽屏下可拖动分类栏、文献列表和助手栏之间的三条竖向分隔线调整宽度，阅读区随之伸缩。双击某条分隔线恢复对应栏的默认宽度；用 Tab 聚焦分隔线后，可按左右键微调（Shift 加速），Home/End 调到最小/最大宽度。拖动时按 Esc 撤销。宽度保存在当前浏览器，刷新后恢复；窗口缩小时自动限制各栏宽度，保留阅读空间。平板和手机继续使用原有的面板切换布局。

连续阅读现支持直接选择 PDF 文字并按 Ctrl+C 复制，也可点击“复制本页文字”。页面图片上叠加从当前页提取的透明文字层，缩放和调整栏宽时同步缩放；选择中的页面不会因滚动而释放。纯扫描页、无文字页会显示“本页无文字层”，本功能不自动 OCR。文字编码缺失或图表、公式等特殊排版可能影响复制结果，可切换“浏览器阅读器”核对原文。文字层由本机 `pdfplumber` 生成，仅保存派生缓存，不更改原始 PDF。Python 依赖见 `app/downloader/requirements.txt`（包含 pdfplumber）；提取失败时图片仍可阅读，并显示原因。

## 启动

安装用户从开始菜单打开 Zhiyue，源码调试使用 `npm run desktop:dev`，本机构建完成后也可运行 `.\start-desktop.cmd`。Tauri 会启动本地服务，再在 WebView2 窗口中加载 Vue 界面。构建和文献库路径见[程序结构与维护](../README.md)。

应用使用项目依赖自带的官方 Pi SDK（`@earendil-works/pi-coding-agent`，当前 1.5.2）；模型与登录配置仍读取本机 `~/.pi/agent`（可用 `PI_CODING_AGENT_DIR` 指定）。可在助手面板的“模型与密钥”中保存或清除 API 密钥、更换默认模型、调整思考强度与上下文压缩阈值，账号登录仍在终端运行 `pi` 完成；未配置时仍可浏览和整理文献。

论文解析和下载使用随包便携 Python（pypdf、pdfplumber、pypdfium2）；Poppler 和 curl 可选。启动前可运行 `.\scripts\download.ps1 doctor` 检查。本地服务优先使用 `LITERATURE_PYTHON`，其次为随包 Python、`app/downloader/.venv` 和 PATH。

## 阅读和提问

助手面板和「阅读笔记」空白页都提供当前论文的两个操作。「值得读吗？」调用 `paper-reading`，在当前对话给出阅读建议和证据定位。「总结全文」调用 `paper-experiments`，把总结提交为笔记草稿，用户确认后写入 `notes/`。

2026-11-17：右侧只使用 Pi Agent，不再提供助手切换。网站改用项目依赖中的官方 Pi SDK 1.5.2，桌面安装包随包分发运行依赖，不再查找本机 Pi 的托管安装；模型和认证配置仍复用本机 `~/.pi/agent`。首次使用先在终端运行 `pi` 完成登录，或点击助手页头的设置按钮填写 API 密钥。设置面板可更换网站新会话的默认模型（同时写入 Pi 全局设置）、保存和清除 API 密钥；账号登录（OAuth）仍需在终端 Pi 中完成。`PI_CODING_AGENT_DIR` 可指定 Pi 配置目录。

Pi 的网页会话提供文献工具，支持流式回答、停止、论文上下文、图片与提取后的文件附件。技能从文献库 `.zhiyue/skills/` 扫描：系统提示只放名称、描述与路径，正文由 `read_skill` 按需读取；不加载 Pi 的全局扩展、全局技能或任意 shell/文件写入工具，技能内的 `.md` 以外文件不会被读取。输入框以 `/` 开头时显示斜杠命令菜单（↑↓ 选择、Enter/Tab 插入、Esc 清空），命令由 `/api/commands` 提供、在 `/api/chats/:id/commands` 执行：`/help`、`/skills` 与 `/compact` 由服务端直接生成回执消息，不进入模型上下文；`/skill:<名称>` 把技能说明展开成本轮用户要求发给模型，聊天记录只保留用户输入的单行指令。命令与普通消息共用同一套选中文献上下文：两者都会带上 `paperIds`、阅读器当前打开的编号 `activePaperId` 与页序 `pdfPage`，由服务端 `normalizePaperContext` 校验（只接受 `L` 编号、最多 6 篇、页序为正整数）并写回会话；提示词会注明哪一篇是“当前打开”、在第几页，以及各篇总页数，因此 `/skill:<名称> 看看这篇` 能定位到正在阅读的文献。Pi 没有可用模型时，页面提示配置模型与密钥，并提供设置入口和重新检测；模型不支持图片时会明确报错。模型返回的推理内容单独收在消息上方的“推理过程”折叠块中，默认收起，随回答增量追加。Pi 生成的笔记或文稿先作为草稿显示在右侧：笔记由用户点击“保存为笔记”后写入 `library/notes/`，跨论文综合和成果由“保存为文稿”写入 `library/synthesis/` 或 `library/outputs/`；同名文件不会被覆盖，必要时自动添加序号；选择丢弃不会留下文件。Pi 聊天显示记录在 `library/.zhiyue/data/pi/chats.json`，Pi SDK 会话在 `library/.zhiyue/data/pi-sessions/`。旧 Codex 聊天仍保存在 `library/.zhiyue/data/chats.json`，网站不再读取或显示。

- 左侧按主题、年份、阅读进度或收藏筛选，也可以搜索题名、作者和 L 编号。“分类”标题旁的加号新建顶层文件夹；右键文件夹打开菜单，可新建子文件夹、重命名、把 PDF 导入该目录，或删除空文件夹（在应用内对话框确认后移到 `.zhiyue/trash/categories/`，可手动找回）；非空文件夹和仍被批次引用的文件夹不会删除。右键空白处或“全部文献”也可新建顶层文件夹；“全部文献”是汇总视图，不能重命名，重命名只作用于实际分类文件夹。鼠标移到文件夹行或键盘聚焦时仍显示铅笔按钮重命名。分类对应 `papers/` 下的实际目录，空文件夹也会列出，新建时自动接续两位编号前缀。点开分类会展开子文件夹，再次点击同一分类即可折叠；有子文件夹的分类在计数前显示折叠箭头。分类只承载归档论文，导入 PDF 是给分类添加文件的入口，不支持在分类里创建任意文本文件。文献卡片可直接拖到任意分类行（含子文件夹）完成移动：拖动期间临时展开所有子文件夹并高亮目标，松手后由库写锁在后台搬文件并同步索引；拖到“全部文献”或当前所在目录不会改动，窄栏收起侧栏、触摸与键盘用户继续用助手工具移动。重命名保留编号，并同步改写 README、笔记、成果、来源记录、批次台账和索引中的路径；改名与后台归档通过库写锁串行，归档进行中会提示稍后重试。中间默认使用“连续阅读”：PDF 页面纵向排列，滚轮可跨页阅读，工具栏自动显示当前物理页序；仍可用前后页按钮或页码跳转，并保持当前位置缩放。在阅读区按住 Ctrl 滚动鼠标滚轮（触控板捏合同样上报为 Ctrl+滚轮）可按 10% 步进缩放页面，范围 100%–200%，缩放时保持当前页内阅读位置；普通滚轮不受影响，工具栏的缩小、适宽和放大按钮与缩放比例保持同步。页面图像按需加载附近页，离得较远的图像会释放，再滚回时重新加载。也可切换已有 Markdown 笔记；笔记模式下工具栏提供删除按钮，确认后把文件移到 `library/.zhiyue/trash/notes/`（带时间戳前缀，可手动找回），笔记计数与索引同步刷新。原文可单独打开并使用浏览器 PDF 阅读器选择文字、搜索。
- 窗口顶部的“导入 PDF”打开导入对话框，切换到研究助手、阅读或下载任务时也可使用：可多选 PDF、选择整个文件夹或把文件与文件夹拖入，一次最多 100 个、单个最大 25 MB；文件夹中的来源记录等非 PDF 文件会被忽略。首次加入单个文件夹时，归档分类按文件夹名自动预选同名分类（忽略开头的编号），没有同名分类时预选以该文件夹名新建的“网站导入（新建）”分类，提交前按编号规则创建目录，归档只使用批次台账中已存在的分类；手动改过分类后不再覆盖，文件夹名不能用作 Windows 目录名时保持原分类。每个文件按文件名预填题名，可逐条修改并展开填写作者、年份和 DOI，统一选择归档分类；勾选已核对题名与作者后提交。文件先上传到网站数据目录，再由统一下载工具依次执行导入、逐条附加、按用户确认记录身份和整批归档；批次、来源记录、README 索引和编号照常生成。SHA-256 相同或库内已归档的 PDF 会跳过并列出原有 L 编号，不重复归档。
- 选择论文会把编号和归档路径加入右侧上下文，最多 6 篇；上下文标签可移除。提供索引不等于已阅读全文，Pi Agent 可以继续调用原文页读取工具。
- 右侧支持流式文字问答、模型选择、新会话、历史会话、停止生成、审批请求处理、笔记草稿预览和补充问题。历史会话行末可以归档或删除。归档后可在「已归档」阅读，恢复后可继续对话。确认删除后，会话移入「回收站」，可恢复到普通列表。回收站保留本地会话记录和 Pi 上下文。
- 助手回答、笔记草稿和 Markdown 笔记支持 LaTeX 公式。行内公式可用 `$...$` 或 `\(...\)`，独立成行的块公式可用 `$$...$$` 或 `\[...\]`。渲染所需的 KaTeX 样式和字体由本地应用提供。
- 在助手输入框下方点“添加文件”，也可将文件拖入输入框或粘贴图片。文件会作为本次提问的附件。每次最多 8 个文件，每个最多 25 MB。支持 PNG/JPEG/WebP/GIF、PDF、TXT/MD/CSV/TSV/JSON、DOCX/XLSX/PPTX。
- 图片作为图像交给 Pi Agent；PDF 初始提取前 8 个物理页，原文工具每次最多 12 页。扫描 PDF 不自动 OCR，空文字层会明确标出；需要时可继续读取或渲染所选原文。Office 附件提取有限的正文 XML 文字，不保证图表、公式、工作表结构和版式。
- 收藏和阅读进度仅在用户操作时写入，生成笔记、打开原文或提问不会自动标记已读。网站标记独立存于 `library/.zhiyue/data/reading.json`，不推断或覆盖旧笔记里的阅读状态。

聊天与附件存放在本机；发送问题时，所选论文索引、实际读取的原文内容、图片和附件提取文字会交给当前助手已配置的模型服务。提示中还包含文献库根目录、选中文献与附件的本机绝对路径；选中只决定初始提示，页读取工具可访问任何已索引的 L 编号。Pi 使用其配置的模型服务、网络、计费及数据处理设置，并非默认离线运行。具体范围见[架构说明](../../ARCHITECTURE.md#模型上下文与数据外发)。

### PDF 英译中

阅读器的「翻译成中文」使用 Pi 默认模型。按钮旁显示服务商和模型；提交后，BabelDOC 在本机解析版面，Pi SDK 将待翻译的文本片段发送给该模型。安装方法见[项目 README](../../README.md#启用-pdf-翻译可选)。任务期间可以继续阅读或切换文献，返回时可查看进度。点击「取消」后等待排版进程与模型请求收尾，再提交新的任务。

完成后可点击「原文 / 中文」按同一物理页和缩放比例切换，也可「导出中文 PDF」。译本关联原文的内容哈希，换分类后仍可查到。已有译本时，点击导出链接旁的「重新生成中文」可用当前默认模型重新翻译。同一模型和排版版本也可重新生成。任务完成后切到新的译本，保留当前物理页和缩放。生成期间、取消后或失败后，仍可阅读和导出已有译本。

译文允许在原区域内重新换行。参考文献按视觉栏序分条，可识别跳号、分离的编号和悬挂缩进的作者年份条目，并保留有明确证据的跨栏、跨页续行。检测和成品校验均在本机完成。轻微越栏且可逐字定位的行会收窄到原栏后重新校验。书目页无法安全分条或回填时，译本恢复该物理页的原文，包括该页正文，并标为「需核对」。缺少可复制中文的页也会标记。须有可复制的中文文字才能发布译本。扫描件需预先 OCR。

### Pi 斜杠命令

助手输入框中的 `/` 菜单包含随包 Pi 1.5.2 的 24 条内置命令，以及 `/mcp`、`/llama` 和文献库加载的技能。`/help` 和 `/skills` 可在未连接模型时使用。

- `/settings`、`/model [服务商/模型]`、`/thinking [强度]`、`/reload` 操作 Zhiyue 的模型与技能设置。
- `/new`、`/resume [会话编号]`、`/name [名称]`、`/session`、`/copy`、`/compact [说明]`、`/hotkeys` 和 `/quit` 在 Zhiyue 中执行。
- 菜单标为「Pi 终端」的命令打开随包 Pi，并将命令填入终端输入框。回车确认执行。会话树、分支、克隆、导出和分享使用当前 Pi 上下文的副本，终端中的改动保存在 `.zhiyue/data/pi-terminal/`。分享、问题报告和登录按 Pi 终端提示确认。
- `/mcp` 和 `/llama` 随 Pi 终端配置启用。Pi 用户安装的额外扩展命令和模板可以在该终端用 `/` 查找。

## 下载任务中心

可以在任务中心按行输入 DOI 或题名，也可粘贴 JSON 条目数组。选择归档分类与下载渠道后提交。优先提供 DOI，题名有歧义时需要补充核对。页面空闲时表单单栏居中，下方列出“导入清单 → 查重下载 → 身份核验 → 归档编号”的流程提示；论文信息框按非空行或 JSON 条目实时显示条数，超过 500 条标红。右侧「任务与批次」只在有进行中任务、失败任务或批次时显示（此时页面恢复双栏）：进行中与失败任务直接列卡片，已完成的任务（包括“刷新索引”产生的维护任务）收进「已完成任务」折叠区，默认收起并显示结束时间，最多列最近 20 条；没有这类内容时不渲染该区域，只在页头说明行显示「历史任务（N）」链接，点开后才会占右栏，再点「收起历史任务」恢复。

一次新任务复用同一套流程：

```text
导入批次 → 本地查重 → 下载或复用 → PDF身份、解析与渲染核验
                                    ↓
                     已核验项归档 → 编号、来源、README和目录更新
                     未通过项保留待办 → 修正信息或人工核对后续跑
```

网页与 Pi Agent 均调用 [统一文献工具](../downloader/README.md)，没有另一套下载器或书目数据库。新任务默认归入 `papers/09_情感综述调研/网站导入/`，可选择其他已有主题；旧批次继续使用原目录。

| 渠道或按钮 | 实际作用 |
| --- | --- |
| 公开来源 | 先查本地，再尝试公开来源；无法获取的记录保留待办 |
| 自动渠道 | 按现有配置尝试渠道，Elsevier 凭据须在启动桌面应用的进程环境中配置 |
| IEEE/机构渠道 | 准备并提交现有 InstSci；需要时在机构工具可见窗口登录 |
| 继续下载 | 对该批次明确重试公开渠道 |
| 提交 IEEE 获取 | 将现有批次提交到机构下载器，不代表 PDF 已取得 |
| 收集机构下载 | 从本批次的固定 InstSci 输出目录匹配并核验 PDF |
| 核验文件 | 复查已记录的文件及身份、解析与渲染结果 |
| 归档入库 | 只归档通过核验的条目，复用已有编号或分配下一编号 |

任务显示“流程结束”表示命令流程结束；是否取得论文应查看“已归档 / 待人工核对 / 待获取权限”等统计与日志。机构浏览器任务异步运行，下载结束后点击“收集机构下载”，再核验和归档。

斜杠命令与技能的关系：不带斜杠时模型按技能描述自行决定是否调用 `read_skill`；`/skill:<名称>` 是显式入口，直接把技能正文放进本轮提示，适合需要强制套用某个流程的场合。技能可写 `disable-model-invocation: true` 只保留命令入口，此时系统提示的能力清单不再列出该技能。想查看当前加载情况可发送 `/skills`，它会列出技能与扫描诊断；`/compact [说明]` 调用 Pi 的会话压缩，把摘要写回同一会话文件，被中断的回答不会重试。

Pi Agent 可用的具名工具：`library_search`、`library_categories`、`create_category`、`rename_category`、`delete_category`、`delete_categories`、`move_paper`、`move_papers`、`read_library_doc`、`paper_outline`、`search_paper_text`、`read_paper_pages`、`render_paper_page`、`download_papers`、`continue_download_batch`、`get_download_status`、`read_skill`、`draft_note`、`draft_document`。`read_library_doc` 只读 README、`notes/`、`synthesis/`、`outputs/` 的 Markdown/文本并支持分段；`paper_outline` 读取 PDF 内嵌目录；`search_paper_text` 在单篇论文文字层中定位关键词；`render_paper_page` 把扫描页、图表或公式渲染成图片。工具结果提供真实任务 ID 与状态；聊天中创建的任务也会进入任务中心。`download_papers` 与 `continue_download_batch` 直接入队，归档前只做自动身份核验，没有逐篇确认；`draft_note` 把单篇笔记草稿交给网页预览，`draft_document` 把综合或成果草稿交给预览；写入前都需要用户确认，不能由模型直接覆盖已有文件。分类工具中 `create_category`、`rename_category`、`move_paper` 直接执行并刷新侧栏。多个删除请求合并到同一张卡片，核对并勾选后点「将所选移入回收站」。非空和仍被批次引用的目录会保留，卡片会显示失败原因。多篇移动可直接告诉助手每个目标分类及对应的 L 编号。助手一次提交任务，可在任务中心查看已移动、已在目标和未完成的明细。

## Vue 前端维护
